W132D 修复工具（适用于已刷 v12 的设备）
================================================================

【设备还没刷飞牛？】

  本工具包只负责"刷完之后"的修复。如果设备还是原厂系统，
  先看同目录下的 刷机教程.md，按里面的步骤把 fnos-w132d-v12.img 刷进去，
  刷好、能开机、能 SSH 之后再回来做下面这些。

【开始之前，先做这三件事】

  1. 激活飞牛
     新装的飞牛第一次开机还不算能用，要用浏览器打开
         http://设备IP
     走完激活 / 初始化流程（建账号、设密码）。
     没激活的话系统没真正跑起来，什么都连不上。

  2. 打开 SSH
     浏览器进飞牛后台 -> 系统设置 -> SSH -> 把 SSH 服务打开。
     不开这个，下面所有批处理都连不上设备。

  3. 改 config.bat
     用记事本打开本文件夹里的 config.bat，改最后两行：

         set "IP=192.168.0.140"      改成你这台飞牛的 IP
         set "USR=admin"             改成飞牛初始化时创建的账号

     IP 在飞牛后台 -> 系统设置 -> 网络 里能看到。
     改完保存就行（这个文件是纯英文的，什么编码都不会乱）。

【怎么用：按编号一个一个双击，不要跳】

     1-HDMI显示.bat      装设备树 + 显示驱动      装完必须重启
     2-重启设备.bat      让设备树 / 驱动生效      输入 y 回车
     3-USB三个口.bat     释放 HUB 复位            立即生效
     4-WiFi无线.bat      装 WiFi 模块 + 固件      要在重启之后跑
     5-屏蔽升级.bat      屏蔽后台系统升级
     6-检查状态.bat      只看不改，确认全部到位
     7-分配空间.bat      从 eMMC 划一块建存储空间（可选，随时可跑）

  为什么不能跳：
    - HDMI 要的设备树是开机时读的，1 号装完必须 2 号重启才生效；
    - WiFi 的底层驱动要靠新设备树里的节点找 SDIO 控制器，
      新树没生效就加载，内核会报 Internal error: Oops（刷一段红字），
      所以 4 号一定要在 2 号重启之后。

  每个窗口跑完会停住，看完按任意键关掉，再双击下一个。

【第一次运行要输密码】

  第一次双击任意一个批处理，会让你输 1~2 次设备密码
  （ssh 登录一次、sudo 一次），这是在装免密登录。
  装好之后，后面所有脚本都不再问密码。

  不成功（密码输错、设备禁了公钥登录）只会警告，功能照样能用，
  只是每次都要手动输密码。

【为什么 HDMI 重启后会失效，这版怎么解决的】

  显示驱动里有个关键模块（HDMI PHY），它是我们自己编的，
  内核里没有任何东西会主动去加载它。而显示控制器（vop）的时钟
  要靠它提供 —— 少了它，vop 一直等着，还不打印任何错误。
  表现就是：装的时候是手动加载的，能亮；重启以后没人再加载，就黑屏。

  这版在 1 号里加了开机自启（/etc/modules-load.d/w132d-hdmi.conf
  + w132d-hdmi.service），保证每次开机先加载 PHY 再加载显示驱动。
  所以现在必须重新跑一次 1 号，再重启，才会一直有效。

  重启后仍然黑屏的话，跑 6 号，把输出发我；里面会显示
  设备树节点在不在、驱动绑没绑上、/var/log/w132d-hdmi.log 最近记录。

【各项到底改了什么】

  1. HDMI
     - 设备树换成 W132D 专用版（原文件备份为 *.dtb.bak-v12）
       新树含 vop@ff840000 / hdmi@ff8d0000 / phy@ffe00000 / display-subsystem，
       以及 WiFi 用的 mmc2 SDIO、/uwe-bsp、/sprd-wlan 节点，
       并把 led-lan（GPIO4_B5）默认电平改成"高"
     - 两个模块装进 /lib/modules/<内核版本>/updates/（优先级高于 kernel/）
         rockchipdrm.ko            原厂那份不支持 rk3528，必须换（备份为 .stock）
         phy-rockchip-inno-hdmi.ko 内部驱动名改成 rk3528-hdmi-phy，
                                   绕开与内核内建驱动 inno-hdmi-phy 的重名冲突
     - 开机自启：先 PHY，后 rockchipdrm（这是重启后不黑屏的关键）

  3. USB 三个口
     靠近 HDMI 的蓝色口走 USB3，一直是好的；另外三个走 GM8220S 四口 HUB。
     它的复位脚是 GPIO4_B5，被 green:lan 这个 LED 占着并按"默认关闭"拉低，
     HUB 就一直处于复位状态，所以三个口都不认设备。
     脚本把它拉高，并装 udev 规则 + systemd 服务保证每次开机自动执行。

  4. WiFi
     芯片是展锐 UWE5621DS（Marlin3E），模块已编译好随包提供，不用再编译。
     校准文件必须同时放 /lib/firmware/ 根目录 ——
     驱动里的路径是硬编码的 /lib/firmware/wifi_56630001_3ant.ini，
     少一层目录就报 LOAD_INI_DATA_FAILED 然后复位。

     脚本会先做三道预检查，任一项不满足就"只放文件、不加载模块"：
        - 本次开机是否已经 Oops 过（是就让你先重启）
        - 设备树里有没有 /uwe-bsp 节点（没有说明 2 号还没重启）
        - SDIO 卡有没有绑上 sdiohal 驱动
     缺一样强行加载就会 Oops。跳过不算失败，重启后系统会自己加载。

  7. 分配空间（可选）
     飞牛首启会把系统盘扩到整块 eMMC 的 99%，后台就永远建不了存储空间。
     这一步把 btrfs 根文件系统在线缩减，再把分区尾巴收回去，空出来的
     未分配空间去 飞牛后台 - 存储空间 - 创建 里用。

     要留多少，在 config.bat 里改 NEWGB，默认 10，建议就是 10：
       32G eMMC  ->  系统盘约 18G + 未分配 10G
     脚本只收不放，动手前会先打印"从多少收到多少"，让你确认一次。
     同时会把 /usr/trim/bin/resize-rootfs.sh 改名停用，
     否则下次开机会被它重新铺满。

  5. 屏蔽升级
     - apt 定时器 mask（apt-daily / unattended-upgrades）
     - 内核与引导包 apt pin 设为 -1，永远装不上
     - 从 /usr/trim/bin 提取的升级域名写进 /etc/hosts -> 0.0.0.0
     系统和 Web 后台都不动，只是升级包下载不到。

  6. 检查状态
     打印内核版本、设备树节点、驱动绑定、DRM 节点、USB 拓扑、wlan0、
     SDIO 绑定、有没有 Oops 过、模块位置、开机自启配置、升级屏蔽。
     只读，随时可跑。

【注意】
  - 千万别点后台的"系统升级"。它会换掉 boot.scr / dtb / 内核，
    这台机器会直接失联。
  - 反复 modprobe -r WiFi 驱动会触发内核 Oops（厂商代码的毛病），
    脚本只在没加载时才加载，别手动去卸它。
  - 看到  Internal error: Oops: 0000000096000004  不用慌：
    那是 WiFi 驱动在设备树没生效时取到空指针，只是这一次加载失败，
    不会写坏任何文件。断电重启一次就好。

【出错怎么办】
  - 提示"连不上设备"：
      飞牛激活了吗？后台 SSH 打开了吗？config.bat 的 IP 对吗？
  - 1 号提示"目标文件不存在"：把窗口里列出的 dtb 文件列表发我
  - 1 号做完重启还是黑屏：跑 6 号，把输出发我
  - 4 号提示"新设备树还没生效"：正常，说明没重启，重启后 WiFi 自动加载

  1~7-*.bat         按编号一个一个双击
  msg\              中文提示文本（bat 只放英文，避免乱码）
