# 中兴 W132D 刷机教程（RKDevTool 线刷飞牛 fnOS）

把还在原厂系统（安卓 / 原厂 Linux）的中兴 W132D，用瑞芯微 MaskROM 线刷方式刷成飞牛 fnOS，
得到一个「能开机、能上网、能 SSH」的底子，然后再用同目录下的 `1~7` 号批处理修好 HDMI / USB / WiFi。

**本教程刷的镜像 = `fnos-w132d-v12.img`**，它是后面所有批处理的基准，不要用别的版本。

## 什么时候需要刷机

| 情况 | 要不要刷 |
| --- | --- |
| 设备还是原厂系统，没装过飞牛 | **要刷** |
| 已经刷过飞牛 v12，只是 HDMI / USB / WiFi 不好用 | **不用刷**，直接用 `1~7` 号批处理 |
| 系统刷坏了，开机没反应 / 一直黑屏 / 反复重启 | **要刷**（先看[救砖](#救砖)） |
| 想把系统升级到官方新版 | **不要刷**，本机已屏蔽升级，刷了会丢 HDMI 修复 |

> 刷机会**清空整块 eMMC**，上面所有数据都会没。有数据先拷出来。

## 第 1 步：装瑞芯微 USB 驱动

1. 解压 `DriverAssitant_v5.1.1.zip`
2. 右键 `DriverInstall.exe` → **以管理员身份运行**
3. 点「驱动安装」，等提示安装成功
4. 关掉窗口

装好后设备管理器里会出现 `Rockusb Device` 这一类设备（现在还没插设备，看不到是正常的）。

> 如果之前装过别的版本、设备管理器里 `Rockusb Device` 带黄色感叹号，先在设备管理器里
> 右键卸载（勾「删除驱动程序」），再重装这一版。

---

## 第 2 步：准备镜像和 loader

1. 解压 `W132D_for_window刷机工具.zip` 到**纯英文路径**，例如 `D:\W132D\`，
   得到 `RKDevTool_v3.37_for_window刷机工具\` 文件夹，`RKDevTool.exe`、`loader.bin`、
   `rk3528\MiniLoaderAll.bin` 都在里面
2. 解压 `w132dfnos固件.zip`，得到 `fnos-w132d-v12.img`，放到本地磁盘
   （**不要放 U 盘、不要放网络盘、不要放中文路径**），例如 `D:\W132D\fnos-w132d-v12.img`
3. `loader.bin` **不用另外准备**，工具文件夹里自带。仓库 `flash\loader.bin` 是备用的另一份，
   只有在自带 loader 认不到设备时再换它（见[故障排查](#故障排查)）

校验镜像（可选但强烈建议）。在 cmd 里执行：

```bat
certutil -hashfile D:\W132D\fnos-w132d-v12.img SHA256
```

应该得到：

```
0967794bc050c57d67d31e71aa33a2b2af5978fcffa18f0123a789fa5d5d4489
```

文件大小应该是 **3,854,565,376 字节**（3.59 GB）。不一样说明下载不完整，重下。

仓库备用 `flash/loader.bin` 的 SHA256 是 `bb8ef990a317b524885cf683c8b0997eb95f94429bdd8929b04102ee27631d08`；
工具包自带的那份不用校验，能正常识别设备就行。

## 第 3 步：让设备进入 MASKROM

这一步是整个刷机里唯一需要动手的环节。**关键点只有一个：复位必须在上电之前就按住**，
顺序错了 SoC 会直接从 eMMC 引导进系统，永远不会停在 MaskROM。

### 标准做法

1. **设备断电**，拔掉电源
2. 把 USB 数据线一头插电脑，另一头插设备上**靠近 HDMI 的那个蓝色 USB3 口**
   （三个黑色 USB2 口走 HUB，刷机时可能识别不到，优先用蓝色口）
3. 用回形针捅住 HDMI 旁边的 **Reset 孔**并保持住
4. **保持按住的同时插上电源适配器**
5. 数 3~5 秒后松开 Reset
6. 打开 RKDevTool，窗口下方状态栏应出现：

   ```
   发现一个MASKROM设备
   ```

看到这一行才算成功。如果显示的是 `发现一个LOADER设备` 也可以刷（说明板子上还有可用的引导）。

### 捅孔没反应怎么办

不同批次的 W132D 外壳不一样，Reset 孔不一定通，这时候拆：

1. 拧下底壳螺丝，取下上盖（注意卡扣，别硬掰）
2. 找到 eMMC 芯片旁边两个测试点（板上一般丝印 `CLK` / `GND`，或在 eMMC 引脚上）
3. 用镊子短接这两点 → **保持短接的同时插电源** → 3 秒后松开
4. RKDevTool 里出现 `发现一个MASKROM设备` 即成功

> 短接法要小心别碰到旁边的电源脚，镊子只碰这两个点。不确定就先拍照发出来问。

### 系统还能进的时候

如果飞牛还能正常启动、能 SSH，可以不拆机：

```sh
sudo reboot loader
```

设备会重启进 LOADER 模式（屏幕一直黑是正常的），RKDevTool 显示 `发现一个LOADER设备`，同样能刷。
如果敲完没反应、照常进了系统，说明这个固件的 u-boot 不支持，还是得拆机短接。

## 第 4 步：RKDevTool 两行配置

打开 RKDevTool，切到 **「下载镜像」** 页（不是「高级功能」），表格里只留**两行**：

| 地址 | 名称 | 路径 |
| --- | --- | --- |
| `0xCCCCCCCC` | Loader | `D:\W132D\RKDevTool_v3.37_for_window刷机工具\loader.bin` |
| `0x00000000` | Image | `D:\W132D\fnos-w132d-v12.img` |

操作：

1. 第一行「路径」格点右侧 `...`，选 `loader.bin`
2. 第二行「路径」格点 `...`，选 `fnos-w132d-v12.img`
3. 多余的第三、第四行一律删掉（右键 → 删除）
4. **勾选右边的「强制按地址写」**

### 为什么必须勾「强制按地址写」

- `0xCCCCCCCC` 是 RKDevTool 给 Bootloader 行留的固定占位地址，不是真实地址，照抄就行；
- `0x00000000` + 强制按地址写 = **从第 0 扇区开始整盘顺序写**。
  我们的镜像自带 GPT 分区表、idbloader、u-boot、boot 分区、rootfs，必须一个字节不差地落到原位置；
- **不勾这一项，工具会按分区表"挑着写"，引导区经常被跳过** —— 结果就是刷完灯亮、但系统起不来，
  看起来像"刷成功了其实什么都没写进去"（空刷）。

> 这一条是踩过三次空刷换来的结论，别省。

---

## 第 5 步：开始写入

1. 确认状态栏是 `发现一个MASKROM设备`
2. 点 **「执行」**
3. 进度条开始跑，右侧日志会打印写入地址和速度

正常情况下：

- 总大小约 3.59 GB，USB2 下大概 **3~10 分钟**；
- 中途**不要拔线、不要动电源、不要点其他按钮**；
- 到 100% 后日志出现 `下载完成` / `Reset Device Success`，设备自动重启。

如果一开始就报错，先看[故障排查](#故障排查)，别反复硬点。

### 验证真的写进去了

刷写前后都可以点 **「读取 Flash 信息」**（有的版本叫 `Get FlashInfo`）：

- 读到 **`30016MB`** 之类的容量 = 通道打通、eMMC 能正常读写；
- 报 `获取 FlashInfo 失败` = **负载没跑起来**，此时点「执行」必然空刷，先解决连接问题。

---

## 第 6 步：首次开机

刷完后设备会自动重启。首次启动比平时慢，**2~3 分钟内别断电**（系统在校验和扩展分区）。

看灯判断进度：

| 灯 | 含义 |
| --- | --- |
| 红灯常亮 / 绿灯心跳闪 | 内核已接管，系统在启动 |
| 只有绿灯常亮不动 | 引导没跑起来，多半是空刷，回[第 5 步](#第-5-步开始写入)重刷 |

然后在路由器后台找设备：

- 主机名一般是 `trim` 或 `fnOS`
- 或者扫网段：`arp -a`、路由器 DHCP 客户端列表

找到 IP 后浏览器打开 `http://设备IP:5666`。

---

## 第 7 步：激活飞牛 + 开 SSH

1. 浏览器进 `http://设备IP:5666`，走完**激活 / 初始化**（设管理员账号密码）
2. 进 **系统设置 → SSH**，把 SSH 服务**打开**
3. 电脑上试一次登录，确认通了：

   ```bat
   ssh 你的账号@设备IP
   ```

能进 shell 就说明底子好了，可以去跑批处理了。

## 刷完之后

刷机只给你一个**能开机、HDMI 黑屏、USB 口不认设备、没有 WiFi** 的飞牛 —— 这是正常的，
v12 用的是 Radxa E20C 的设备树，硬件差异都还在。

接着在 Windows 上按编号跑本仓库的批处理：

```
1-HDMI显示.bat    →  2-重启设备.bat  →  3-USB三个口.bat
→  4-WiFi无线.bat  →  5-屏蔽升级.bat  →  6-检查状态.bat  →  7-分配空间.bat
```

顺序和原因见 [参照我的博客](https://www.320826.xyz/2026/11/w132d-hdmi-usb-wifi.html)。**先把 `config.bat` 里的 IP 和账号改成你自己的。**

## 故障排查

### 设备管理器里没有 Rockusb / 带黄色感叹号

- 驱动没装好：重跑 `DriverInstall.exe`（管理员身份）
- 装了但没生效：设备管理器 → 卸载设备 → 勾「删除驱动程序」→ 重新插拔 → 重装
- USB 线是充电线：换一根能传数据的（插手机能识别存储的那种）

### RKDevTool 一直显示「没有发现设备」

按可能性排序：

1. **上电顺序错了** —— 必须「先按住 Reset → 再插电源 → 再插 USB」或「先插 USB → 按住 Reset → 插电源」
   两种都试一遍，关键是**复位要在通电之前就按住**
2. **插错口** —— 换蓝色 USB3 口；三个黑色 USB2 口走 HUB，MaskROM 阶段可能不枚举
3. **没接电源** —— 只靠 USB 供电时 DDR 初始化会失败，**必须接原装电源适配器**
4. **Reset 孔不通** —— 拆壳短接（见[第 3 步](#第-3-步让设备进入-maskrom)）
5. 换一台电脑试（有些主板的 USB 口供电不足 / 走了 Hub）

### 显示 MASKROM 但「获取 FlashInfo 失败」

- 电源没接或接触不良 → 换电源口、确认适配器灯亮
- USB 线质量差 → 换短线、直插主板后置 USB 口（别用前面板、别用 Hub）
- 负载没跑起来 → 拔电重进一次 MaskROM，再点「读取 Flash 信息」

### 刷到一半报错 / 卡住不动

- 已经写进去一部分数据了，**设备现在是不完整状态**，必须重刷
- 拔电 → 重新进 MaskROM → 用同一个镜像重刷，不要中途换镜像

### 刷完还是绿灯常亮、系统起不来

这是**空刷**的典型表现：

- 检查「强制按地址写」有没有勾
- 检查「读取 Flash 信息」能不能读到 30016MB
- 检查镜像 SHA256 对不对（损坏的镜像写入会静默失败）
- 检查是不是只写了 Image 行、Loader 行没写

### 刷完能开机但没网

- 网线插的是不是 `WAN` 口（W132D 只有一个网口，插错不了）
- 路由器有没有给 DHCP；灯亮不亮
- 换根网线试

## 救砖

只要还能进 MASKROM，砖就一定能救回来。

1. 拔电源
2. 拆壳短接（或捅 Reset 孔）+ 插电源
3. RKDevTool 出现 `发现一个MASKROM设备`
4. 按[第 4 步](#第-4-步rkdevtool-两行配置)配两行 + 勾「强制按地址写」
5. 重刷 `fnos-w132d-v12.img`

MaskROM 是 SoC 内部固化的，刷写失败、断电、刷错镜像都破坏不了它 —— **这就是最后的保底**。

## 镜像说明

`fnos-w132d-v12.img`（3,854,565,376 字节，SHA256 `0967794b...`）的结构：

| 位置 | 内容 |
| --- | --- |
| LBA 64 | idbloader（DDR 初始化 + SPL） |
| LBA 16384 | u-boot |
| LBA 65536 起 375 MiB | p1 `BOOT`（ext4，内核 + 设备树 + `fnEnv.txt`） |
| LBA 866304 起 3245 MiB | p2 `rootfs`（btrfs，飞牛系统） |

镜像总长 3.59 GiB，剩下的是 GPT 备份表位置；刷进 30 GB 的 eMMC 后，飞牛首启会把
`rootfs` 扩到整块盘的 99%（约 28 GB），所以第 7 步「分配空间」必须做。

镜像里的设备树是 **Radxa E20C 的**，被换成了打过补丁的 W132D 版本（`rk3528-radxa-e24c.dtb` 槽位，
`fnEnv.txt` 指过去），所以能开机、能上网，但显示 / USB HUB / WiFi 还得靠批处理补。

> 镜像不含飞牛官方安装包以外的闭源组件；`flash/loader.bin` 是 Rockchip 原厂 USB loader，
> 版权归 Rockchip（见 `flash/COPYING.rkbin`），仅用于让 MaskROM 进入可读写 eMMC 的状态。
